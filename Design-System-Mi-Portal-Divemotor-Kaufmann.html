El sistema combina la identidad Divemotor con una base regional reutilizable: sobria, operacional, accesible y preparada para escalar interfaces de clientes corporativos.

02 | Marca

Identidad base: moderna, simple y confiable.

El BrandBook plantea una línea simple, moderna y elegante, con experiencia intuitiva y agradable. El sitio público refuerza una composición de alto contraste: negro, blanco, azul intenso, fotografía de vehículos y títulos condensados.

Secundario#E6750C

Superficie#F5F6F8

Modo Divemotor

Usa azul Divemotor como acción primaria, negro para navegación superior y naranja como apoyo comercial o foco secundario.

  • Títulos: Roboto Condensed, alto impacto y buena lectura en módulos.
  • Cuerpo: Roboto, escala compacta para datos y formularios.
  • Imágenes: vehículos con margen de paisaje, sobreimpresiones oscuras y contenido legible.

Modo Kaufmann

La librería debe permitir theme switching para Chile sin duplicar componentes: cambia tokens de marca, mantiene layout, estados y comportamiento.

  • Primary cambia a azul Kaufmann, con cian como acento.
  • Componentes comparten estructura, accesibilidad y APIs.
  • El país define formatos, textos legales, monedas y documentos.

06 | Angular

Librería propuesta.

Separar piezas visuales, patrones de dominio y servicios transversales permitirá que Chile y Perú avancen juntos sin acoplar reglas locales.

@mi-portal/tokens

  • Colores, tipografías, radios, sombras.
  • Themes: divemotor, kaufmann.
  • Mixins SCSS y CSS variables.

@mi-portal/ui

  • Button, input, select, radio, checkbox.
  • Alert, badge, card, table, accordion.
  • Menu, tabs, modal, drawer, stepper.

@mi-portal/layout

  • App shell, topbar, sidebar.
  • Page header, grid, empty states.
  • Responsive utilities.

@mi-portal/domain

  • Vehicle card, contract summary.
  • Payment status, service appointment.
  • Document list, request timeline.

@mi-portal/forms

  • Form field wrapper.
  • Validaciones RUT/RUC.
  • Máscaras de moneda, teléfono y documento.

@mi-portal/storybook

  • Catálogo vivo de componentes.
  • Estados, accesibilidad y ejemplos.
  • Documentación para frontend y UX.

07 | Gobierno

Reglas para que el sistema no se fragmente.

Hacer

  • Documentar cada componente con propósito, anatomía, estados y accesibilidad.
  • Definir ejemplos por dominio: flota, pagos, taller, contratos, certificados.
  • Versionar cambios con semver y changelog para equipos Chile/Perú.
  • Medir contraste, foco visible, navegación por teclado y responsive.

Evitar

  • Crear variantes visuales por país dentro del componente.
  • Usar color como único indicador de estado.
  • Mezclar lógica de negocio dentro de componentes visuales.
  • Diseñar pantallas nuevas sin revisar Storybook y patrones existentes.
Recomendación: partir con un MVP de componentes core y 3 patrones de dominio prioritarios: tabla de flota, card de vehículo y flujo de agendamiento. Eso habilita la mayoría de pantallas del portal sin sobrediseñar.
08 | Roadmap

Plan sugerido de implementación.

Semana 1

Tokens, themes, tipografía, botones, campos, badges, alerts y setup de Storybook.

Semana 2

Shell, sidebar, tablas, cards, filtros, paginación, estados vacíos y loading.

Semana 3

Acordeones, steppers, modales, formularios complejos, validaciones RUT/RUC y máscaras.

Semana 4

Patrones de dominio, pruebas de accesibilidad, handoff a frontend y primer wireframe completo.
